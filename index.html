OPUS

Automated OSS Contribution Engine  /  2025–present
Live
The Problem
Open source projects need documentation, tests, and small fixes — but maintainers are overwhelmed and contributors face high onboarding friction. Most AI-assisted contribution tools produce generic patches that get rejected because they don't understand the project's conventions.
What I Built
OPUS is a headless Claude Code CLI engine that discovers real GitHub repositories, analyzes their codebase conventions and open issues, generates targeted doc/test/fix PRs that match the project's style, and submits them autonomously. It reads CONTRIBUTING.md, maps existing test patterns, and produces PRs that look like they were written by a contributor who actually read the codebase. It's self-improving: each merged PR feeds back into its pattern library.
# OPUS headless execution — no human in the loop
claude -p "analyze repo conventions and generate PR" \
--context repo_url \
--output pr_draft.md

# Self-improving: merged PRs update the pattern library
opus.patterns.update(merged_pr.diff, accepted=True)
Outcome
Submits doc and test PRs to real GitHub repositories with acceptance rates that outperform generic AI tooling. The engine runs fully autonomously — finds repos, generates contributions, opens PRs, and tracks acceptance — without human intervention per submission.

ai-crm-agents

Production Multi-Agent CRM System  /  2025–present
17 Stars
The Problem
CRM tools capture data but don't act on it. Sales teams spend hours reading contact histories, writing follow-up sequences, and manually qualifying leads — work that is repetitive, pattern-driven, and ideal for agents. The challenge: building agents that actually understand sales context, not just route tickets.
What I Built
A production multi-agent CRM system with 6 specialized agents operating in a coordinated LangGraph workflow: a Lead Qualifier that scores inbound contacts, an Outreach Writer that generates personalized email sequences, a Follow-up Scheduler that manages cadence, a Meeting Booker that handles calendar coordination, a Deal Analyst that tracks pipeline health, and an Insights Summarizer that surfaces weekly patterns. Each agent has bounded context, validated inputs/outputs, and retry logic.
# 6-agent LangGraph workflow
graph = StateGraph(CRMState)
graph.add_node("qualify", lead_qualifier_agent)
graph.add_node("outreach", outreach_writer_agent)
graph.add_node("schedule", follow_up_scheduler)
graph.add_node("analyze", deal_analyst_agent)
graph.add_edge("qualify", "outreach")
graph.add_edge("outreach", "schedule")
Outcome
17 GitHub stars from the community. Used by early-stage startups as a foundation for their own CRM automation. Demonstrates real production patterns: state management, agent handoffs, error recovery, and observability via LangSmith tracing.
